Решение [тестового задания для AQA-стажёра](https://github.com/uchiru/aqa-intern-challenge). Исправлены два исходных автотеста и добавлен **один дополнительный тест** — закрытие и повторное открытие виджета. Ссылка на исходный проект и его лицензия сохранены.

## Демонстрация

Скриншоты сделаны автотестами на реальном сайте после проверки заголовков и загрузки формы. При запуске они также прикладываются к HTML-отчёту.

### Открытие виджета

После нажатия «Помощь» отображается база знаний с заголовком «База знаний Учи.ру».

![Открытый виджет базы знаний Учи.ру](docs/screenshots/widget-open.png)

### Переход к поддержке

Тест открывает статью «Как написать в службу поддержки?» и нажимает «Написать нам». В результате отображается форма «Связь с поддержкой»; сообщение не отправляется.

![Форма связи с поддержкой после перехода из статьи](docs/screenshots/contact-support.png)

## Быстрый старт

Выберите один из трёх способов. В каждом варианте один блок команд: скопируйте его целиком и вставьте в указанную консоль. Запускайте из папки, в которой ещё нет каталога `aqa-intern-challenge`: первая команда скачает проект и создаст его.

Для всех способов нужен доступ к `https://uchi.ru` и CDN виджета. Учётная запись Учи.ру не требуется.

VPN может вызывать таймауты загрузки сайта или виджета; при таких ошибках отключите его и повторите запуск.

### Windows 10/11

Нужны установленные **Git** и **Node.js 22** с npm. Откройте **Командную строку (cmd)** и вставьте блок:

```bat
git clone https://github.com/huksleva/aqa-intern-challenge.git
cd aqa-intern-challenge
npm ci
npm run typecheck
npx playwright install chromium
npm test
```

После завершения тестов HTML-отчёт автоматически откроется в браузере. Сервер отчёта доступен по адресу [http://127.0.0.1:9323](http://127.0.0.1:9323) и работает до нажатия `Ctrl+C`.

### Linux и macOS

Нужны установленные **Git** и **Node.js 22** с npm. Откройте **терминал (bash или zsh)** и вставьте блок:

```sh
git clone https://github.com/huksleva/aqa-intern-challenge.git
cd aqa-intern-challenge
npm ci
npm run typecheck
npx playwright install --with-deps chromium
npm test
```

На Linux команда установки Chromium также устанавливает системные зависимости и может запросить пароль `sudo`. После завершения тестов HTML-отчёт автоматически откроется в браузере по адресу [http://127.0.0.1:9323](http://127.0.0.1:9323). Для остановки сервера отчёта нажмите `Ctrl+C`.

### Запуск в Docker

Нужны **Git** и запущенный **Docker Desktop в режиме Linux containers** либо **Docker Engine с Compose**. Блок подходит для cmd, PowerShell и терминала Linux/macOS:

```shell
git clone https://github.com/huksleva/aqa-intern-challenge.git
cd aqa-intern-challenge
docker compose run --build --rm tests
docker compose up --build report
```

Первая команда Docker собирает образ, проверяет типы и запускает три теста. Следующая поднимает сервер полученного отчёта и выводит его адрес в консоль: откройте [http://127.0.0.1:9323](http://127.0.0.1:9323) в браузере. Для остановки нажмите `Ctrl+C`.

Node.js, Chromium и системные зависимости находятся внутри официального образа `mcr.microsoft.com/playwright:v1.64.0-noble`; версия совпадает с `@playwright/test`. Отчёт и диагностика сохраняются на компьютере в `playwright-report/` и `test-results/`. Сервер отчёта доступен только на локальном компьютере.

## Дополнительные команды

Выполняйте команды из папки проекта. По умолчанию тесты работают в Chromium без открытия окна браузера. При запуске через npm HTML-отчёт открывается автоматически после завершения тестов, включая неуспешный результат. В CI и Docker автоматическое открытие отключено. Если порт 9323 занят сервером предыдущего отчёта, остановите его через `Ctrl+C` перед новым запуском.

| Команда | Для чего |
| --- | --- |
| `npm test` | Повторно запустить все три теста и открыть отчёт |
| `npm run typecheck` | Проверить типы, неиспользуемый код и синтаксис скрипта отчёта |
| `npm test -- --headed` | Запустить с видимым окном браузера |
| `npm test -- --ui` | Открыть интерактивный режим Playwright |
| `npx playwright test --list` | Посмотреть список сценариев |
| `npm run test:report` | Открыть HTML-отчёт последнего запуска |
| `docker compose run --build --rm tests` | Повторно запустить тесты в Docker |
| `docker compose up --build report` | Открыть сервер отчёта Docker на порту 9323 |
| `docker compose run --rm tests npm run typecheck` | Проверить типы в собранном контейнере |
| `docker compose down` | Удалить остановленный контейнер сервера отчёта и сеть Compose |

## Сценарии

| Тест | Проверка | Ожидаемый результат |
| --- | --- | --- |
| `opens` | Нажать кнопку открытия виджета | Виджет виден, заголовок — «База знаний Учи.ру» |
| `has correct title` | Открыть статью «Как написать в службу поддержки?» и нажать «Написать нам» | Заголовок меняется на «Связь с поддержкой» |
| `closes and reopens` | Открыть, закрыть и снова открыть виджет | После закрытия виджет скрыт и кнопка открытия видна; после повторного открытия отображается база знаний |

Третий сценарий — дополнительный тест по условию задания. Обращение в службу поддержки не отправляется.

### Страница и ожидания

Тесты открывают [`/signin/main`](https://uchi.ru/signin/main) — публичную страницу выбора входа с виджетом «Помощь». На главной странице есть ссылка «Войти другим способом», которая ведёт на этот маршрут. Сам `/` может показывать другую версию главной без виджета.

Готовность страницы определяется по видимой кнопке `data-test="openWidget"`. Навигация ждёт начала ответа (`commit`), затем тест ждёт кнопку; зависшие сторонние скрипты не удерживают его на событии `DOMContentLoaded`.

Перед сценариями один раз подготавливается анонимная сессия. Каждый тест получает отдельные контекст и страницу с копией этого начального состояния; изменения предыдущего теста не передаются следующему. Авторизация не выполняется, данные сессии хранятся только в памяти. Это не заменяет доступ к сайту и CDN.

На подготовку страницы выделено до трёх попыток по 20 секунд. Перед каждой попыткой открывается `about:blank`, чтобы отменить запросы и отложенные перенаправления предыдущей страницы. Повторяются только таймауты подготовки и прерванная перенаправлением навигация; остальные ошибки передаются в отчёт. Каждая попытка видна отдельным шагом, включая неудачные. Если кнопка не появилась за все попытки, тест падает.

Проверки открытия, перехода к форме и закрытия выполняются один раз: автоматические повторы тестов отключены (`retries: 0`). Общий лимит теста — 90 секунд, проверки результата — 10 секунд. Обработчик cookie-баннера нажимает видимую кнопку «принять» и ожидает его скрытия. Фиксированных пауз нет.

## Что исправлено

| Проблема | Изменение |
| --- | --- |
| `DOMContentLoaded` не наступал из-за зависших скриптов; при повторной загрузке мешало отложенное перенаправление | Добавлено ограниченное восстановление загрузки с ожиданием кнопки виджета и очисткой предыдущей страницы |
| HTML-отчёт на Windows слушал недоступный `::1` | Локальный сервер закреплён на `127.0.0.1`; Docker использует отдельную команду с `0.0.0.0` внутри контейнера |
| Cookie-баннер перекрывал кнопку «Помощь» | Добавлен обработчик видимого баннера через `page.addLocatorHandler()`, без принудительного клика сквозь перекрытие |
| Кнопка открытия зависела от устаревшего родительского CSS-класса | Использован `data-test="openWidget"` |
| `all()` мог вернуть пустой список до загрузки статей; статья выбиралась по позиции | Статья выбирается локатором по точному названию с ожиданием появления |
| Кнопка и заголовок проверялись ненадёжно | Кнопка находится по роли и имени; заголовок проверяется через `toHaveText()` |
| На десктопе кнопка закрытия в заголовке скрыта | Использована видимая внешняя кнопка закрытия |
| Исходная версия Playwright имела известную уязвимость | Playwright обновлён до **1.64.0** и закреплён в `package.json` и lock-файле |

Контейнер виджета и внешняя кнопка закрытия находятся по префиксам CSS-модулей: подходящих тестовых атрибутов или доступного имени у них нет. Эти локаторы могут потребовать обновления при изменении разметки сайта.

| Проверка | Результат |
| --- | --- |
| `npm ci` и `npm audit` | Установка из lock-файла выполнена; известных уязвимостей на момент проверки — 0 |
| `npm run typecheck` | Типы, неиспользуемые переменные/параметры и синтаксис скрипта отчёта проверены |
| `npx playwright test --list` | Ровно 3 теста в одном файле |
| Windows | Пользовательский запуск без VPN — 3/3; при контрольном запуске с VPN воспроизведены таймауты загрузки |
| Docker | Образ собран, статические проверки пройдены; пользовательский запуск без VPN — 3/3 |
| HTML-отчёт | Рабочая ссылка на локальный адрес, HTTP 200; остановка сервера и ошибки отсутствующего отчёта проверены |

Актуальный результат CI и отчёт каждого запуска доступны во вкладке [Actions](https://github.com/huksleva/aqa-intern-challenge/actions); бейдж в начале README показывает состояние workflow.

Тесты работают с реальным публичным сайтом: ответы сервера и скрипты не подменяются. Доступность сайта, CDN, VPN и изменения интерфейса влияют на результат. Успешный прогон подтверждает результат конкретного запуска. При недоступности страницы тест падает, а диагностика сохраняется в отчёте.

### Отчёт и диагностика

HTML-отчёт находится в `playwright-report/` и автоматически открывается после локального запуска. Каждый сценарий разбит на именованные шаги через `test.step()`: в отчёте видно, на каком действии произошёл сбой. Скриншоты успешных состояний прикладываются к отчёту. На создание каждого снимка отводится 5 секунд. Если оно задерживается из-за загрузки шрифта, вместо снимка прикладывается текст причины; результаты проверок интерфейса сохраняются. Другие ошибки создания снимка не подавляются. При падении в `test-results/` сохраняются скриншот ошибки и trace:

```shell
npm run test:report
npx playwright show-trace path/to/trace.zip
```

Чтобы отключить автоматическое открытие для отдельного запуска, задайте переменную `PLAYWRIGHT_HTML_OPEN=never` (PowerShell: `$env:PLAYWRIGHT_HTML_OPEN = 'never'`, cmd: `set PLAYWRIGHT_HTML_OPEN=never`). Для возврата автоматического открытия удалите эту переменную (PowerShell: `Remove-Item Env:PLAYWRIGHT_HTML_OPEN`, cmd: `set PLAYWRIGHT_HTML_OPEN=`). В последней команде нужно указать путь к конкретному файлу `trace.zip`. Отчёты, зависимости и временные файлы исключены из Git.

## GitHub Actions

Workflow [Playwright tests](.github/workflows/playwright.yml) запускает три сценария при push и Pull Request в `master`. Его также можно запустить вручную во вкладке **Actions**. Параметр **Run tests in Docker** переключает ручной запуск на контейнер; автоматические запуски по push и Pull Request используют npm.

CI устанавливает Node.js из `.nvmrc` и зависимости из lock-файла, выполняет `npm run typecheck` и проверяет конфигурацию Docker Compose. В обычном запуске затем устанавливает Chromium и выполняет `npm test -- --workers=1`. Отчёт и диагностика сохраняются как артефакт на 7 дней, в том числе при падении. Бейдж в начале README показывает фактический результат CI. Неудачные попытки подготовки страницы видны в именованных шагах отчёта. Повторы самих тестов отключены. Тесты не пропускаются при недоступности сайта.

## Структура

```text
docs/screenshots/              # Снимки реального виджета для README
tests/
├── fixtures.ts                # Начальная анонимная сессия и изоляция тестов
├── widget.page.ts              # Локаторы и действия с виджетом
└── widget.spec.ts              # Два исходных теста и один дополнительный
.github/
├── workflows/playwright.yml   # Запуск в CI и сохранение отчёта
├── ISSUE_TEMPLATE/            # Шаблоны ошибок и предложений
├── PULL_REQUEST_TEMPLATE.md   # Описание изменений и проверки
└── CODEOWNERS                 # Владелец для ревью изменений
playwright.config.ts           # Chromium, таймауты, отчёт и trace
tsconfig.json                  # Строгая проверка типов конфигурации и тестов
scripts/docker-report.cjs      # Рабочий адрес отчёта Docker в консоли
Dockerfile                     # Окружение Playwright и проверки при сборке
compose.yaml                   # Запуск тестов и отдельный сервер отчёта
.dockerignore                  # Только необходимые файлы в контексте сборки
package-lock.json              # Зафиксированные зависимости
```
